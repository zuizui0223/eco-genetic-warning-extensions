# Phase T — dynamic partner architecture at matched expected support

## Question

> Does temporal partner availability change the functional-loss process when expected aggregate interaction support is held constant, and does contribution concentration amplify that effect?

This phase is intentionally narrower than the superseded low-replicate rewiring-rescue question. It does **not** ask whether an R3 label can be converted to R4. The primary estimands are pooled functional-loss incidence and high-precision between-block heterogeneity.

## Why this test follows the precision audit

Phase N showed that the original one-partner-loss R4→R3 result disappeared at high precision. Therefore static partner loss is not a valid opening premise for a rewiring-rescue experiment.

What remains unresolved is whether explicit **temporal partner structure** matters when average interaction support is controlled. A scalar multiplier contains no information about the temporal variance generated by partner availability or about how contribution is distributed among partners.

## Fixed conditions

All conditions use the Phase-G/N anchor, the exact historical master seeds `20290610–20290614`, 100 attempted replicates per seed, and the same deterioration schedule.

1. **constant support 0.75** — the exact Phase-N `even_redundant` closure, used as the locked comparator;
2. **even dynamic** — four partners with weights `(0.25, 0.25, 0.25, 0.25)`;
3. **dominant dynamic** — weights `(0.70, 0.10, 0.10, 0.10)`.

For both dynamic conditions, each partner is independently available in each generation with probability `0.75`. The same availability draws are reused for even and dominant architectures within each trajectory.

## Matched expectation, different variance

For architecture weights `w_i` and independent availability indicators `Z_i ~ Bernoulli(0.75)`, realised network support is

`S_t = sum_i w_i Z_i(t)`.

Because the weights sum to one,

`E[S_t] = 0.75`

for both dynamic architectures, exactly matching the constant-support comparator.

The intended difference is support variance:

- even: `Var(S)=0.046875`;
- dominant: `Var(S)=0.0975`.

Thus Phase T does **not** match realised support generation by generation. It matches expected support and tests whether intermittency and contribution concentration matter under the nonlinear eco-genetic life cycle.

## Network mapping

The network has one focal functional node and four partner nodes. Partner availability is a stochastic network state. Per-generation support is the sum of active partner weights and multiplies the parent's interaction-support signal during deterioration.

Network availability uses a separate RNG so that adding network dynamics does not mechanically shift the parent's local recruitment/drift random stream. Even and dominant conditions receive the exact same network availability draws.

## Opening rule

No dynamic-network result is interpreted unless:

- the constant `0.75` condition exactly reproduces every original first-20 Phase-G even-loss eligible/loss prefix;
- the constant condition exactly reproduces the five locked 100-attempt Phase-N even-redundant blocks: `51/86, 45/90, 45/86, 46/91, 53/88`;
- baseline eligibility is identical across all paired conditions.

## Primary estimands

For each condition:

- pooled realised functional-loss incidence;
- Pearson equal-rate diagnostic across five 100-attempt seed blocks.

Paired exact McNemar contrasts are reported for:

- even dynamic vs constant;
- dominant dynamic vs constant;
- dominant dynamic vs even dynamic.

Network diagnostics report realised mean support, temporal support variance and zero-support generation frequency.

## Decision logic

Phase T records a dynamic-network effect if at least one preregistered dynamic condition shows detectable block heterogeneity or if a paired marginal-loss contrast is significant at the fixed 0.05 level. The even-vs-dominant comparison specifically tests contribution concentration under shared partner-availability draws.

A null result is equally terminal: it means this first matched-expectation temporal network closure does not alter the population-level loss estimands at the tested anchor.

## Rewiring boundary

Adaptive rewiring is **not included** in Phase T. Rewiring is opened only as a new prospective phase if Phase T first establishes a temporal network effect whose mechanism needs decomposition. This prevents returning to the obsolete goal of tuning rewiring until a historical R3/R4 screen changes.

## Representation boundary

Partner availability is stochastic but has no explicit partner abundance dynamics, coextinction, spatial partner movement, adaptive rewiring or multispecies feedback. This is an explicit temporal partner-state closure, not a full ecological network.

## Stop rule

Run the three declared conditions once. Do not alter availability probability, contribution weights, correlation structure, seeds, historical screen or precision after observing outcomes merely to obtain a network effect.
