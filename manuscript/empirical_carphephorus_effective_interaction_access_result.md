# Carphephorus realised-interaction discovery — identifiable structure, raw execution blocked

## Project-level decision

Two distinct decisions are retained rather than collapsed:

1. **schema/process structure: `realised_interaction_state_identifiable`** from public Dryad metadata plus the pinned author analysis code;
2. **row-level project execution: `raw_execution_not_identifiable_in_current_execution`** because no public Dryad byte stream could be retrieved by the locked GitHub Actions run.

This is an access boundary, not an ecological null.

## Why the state structure is identifiable

Dryad doi:`10.5061/dryad.w9ghx3g48` publicly describes the fixed files and variables. The metadata/README declares:

- `CARBEL-arthropods.csv`: `plant_ID`, `sampling_round`, `visitor_type` and other observation fields;
- `CARBEL-floral.csv`: `plant_ID`, `sampling_round`, focal/local floral variables;
- `CARBEL-seeds.csv`: `plant_ID`, `viable`, `nonviable`, `no_predation` and seed-head identifiers;
- `Patch_type.csv`: `Block`, `Patch`, `Type`.

The pinned author code `hultingk/review-SRS-CARBEL@622e5266db24e99a983bcf89d63a2258ebf93662` independently declares the exact process mapping used by the source analysis:

- count `visitor_type == "pollinator"` by `plant_ID × sampling_round`;
- average pollinator visitation by focal plant;
- join the visitation summary to seed data by `plant_ID`;
- derive `pollination_rate = (viable + no_predation) / (viable + no_predation + nonviable)`;
- attach patch type by block/patch.

Therefore the preregistered structural criterion for a realised-interaction state is satisfied without inventing a join key or outcome.

## Why row-level execution is closed

Workflow run `32818704134` resolved the Dryad dataset metadata and fixed file ID for `CARBEL-arthropods.csv` (`4513267`) before attempting any row-level read. All three public byte routes available to the adapter failed:

- REST file download: HTTP 401;
- Stash file-stream route: HTTP 403;
- legacy file-stream route: HTTP 403.

The workflow stopped before reading a CSV header or data row. No visitation summary, pollination outcome, coefficient, effect direction or p-value was produced.

Because repeated Dryad access-route tuning has already produced the same boundary in earlier campaigns, no downloader search is opened here. The discovery workflow is frozen to manual-only after this result.

## Scientific use

This system remains an unusually good **measurement target** because the source programme directly links focal-plant realised visitation to reproductive/pollination outcome in an experimental fragmentation landscape. The source publication reports that connectivity increased pollinator visitation while connectivity did not change fruit–flower ratio; those published findings remain literature evidence, not a new held-out result generated by this repository.

The next project-generated analysis moves to an independently machine-accessible archive with realised visitation and reproductive function rather than substituting a weaker availability proxy or continuing access tuning.
